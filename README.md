# AutoM

AutoM은 AI로 **네이버 블로그 글**, **인스타그램 카드뉴스**, **YouTube 영상 초안**을 만드는 Windows 데스크톱 프로그램입니다.
모든 작업과 결과물은 내 컴퓨터 안에서 처리되며, 별도의 서버로 원고나 계정 정보를 보내지 않습니다.

프로그램은 두 가지로 나뉩니다.

| | AutoM | AutoM Creator |
|---|---|---|
| 대상 | 네이버 블로그만 사용하는 경우 | 블로그·인스타그램·유튜브를 함께 쓰는 경우 |
| 화면 | 블로그 / 발행 기록 / 설정 | 대시보드 / 블로그 / 인스타그램 / 유튜브 / 발행 기록 / 설정 |
| 실행 | `npm start` | `npm run start:creator` |

두 앱은 설정과 발행 기록을 **서로 다른 폴더**에 저장하므로 섞이지 않습니다.

---

## 무엇을 할 수 있나요

### 1. 네이버 블로그

키워드를 넣으면 AI가 제목·본문·태그를 쓰고, 본문 흐름에 맞는 이미지를 만들어 넣습니다.
발행 방식은 네 가지 중에서 고릅니다.

| 방식 | 하는 일 | 실제로 글이 올라가나요? |
|---|---|---|
| **반자동** | 글과 이미지를 만들어 내 폴더에 저장 | 아니요 (직접 올립니다) |
| **확인 후 발행** | 미리보기로 확인하고 버튼을 눌러야 게시 | 사용자가 누를 때만 |
| **완전자동** | 만들자마자 바로 게시 | 예 |
| **예약발행** | 네이버 서버에 미래 시각으로 예약 등록 | 예 (예약 시각에) |

계정을 보호하기 위한 안전장치가 걸려 있습니다.

- 완전자동·예약발행은 **한 번에 최대 3개**까지만 실행됩니다.
- 완전자동은 글과 글 사이에 **최소 30분**을 기다립니다. (설정에서 늘릴 수 있음)
- 예약은 **지금부터 20분 뒤부터**, **10분 단위**로, **1년 이내**만 가능합니다.
- 이미 발행한 키워드는 자동·예약 발행에서 **다시 쓸 수 없습니다.**
- 완전자동·예약발행을 처음 고를 때 확인창이 한 번 뜹니다.

### 2. 인스타그램

주제를 넣으면 3~10장짜리 카드뉴스 이미지(PNG)와 게시 문구를 만듭니다.
문구를 확인·수정한 뒤 **'실제 발행'** 버튼으로 연결된 계정에 바로 올리거나, 저장된 폴더에서 파일을 꺼내 직접 올릴 수 있습니다.

### 3. YouTube

주제를 넣으면 대본, 장면별 이미지, 자막(SRT), 무음 영상 파일까지 만들어 폴더에 저장합니다.

> **AutoM은 YouTube에 자동으로 업로드하지 않습니다.**
> 직접 목소리를 녹음하고 편집해서 올리는 것을 전제로, '재료'까지만 만들어 줍니다.
> 결과 화면에서 CapCut 편집 페이지와 YouTube 업로드 페이지를 바로 열 수 있습니다.

### 공통 안전장치

- **자동 품질 점검**: 글자 수, 소제목, 이미지·태그 개수, 과장 표현, 키워드 남용, 과거 글과의 중복을 검사합니다. 기준에 걸리면 발행을 막습니다.
- **민감 주제 고지문**: 건강·금융처럼 민감한 주제는 분야에 맞는 안내 문구를 자동으로 붙입니다.
- **미리보기에서 글을 고치면** 발행 직전에 품질 검사를 다시 합니다.
- **외부 주소 열기 제한**: 발행 기록의 링크는 네이버·인스타그램의 정상 주소만 열립니다.
- **업로드 파일 제한**: 이 프로그램이 출력 폴더에 만든 PNG만 업로드됩니다.

## 준비하기

### 1. 설치

```bash
npm install
npx playwright install chromium
```

`npx playwright install chromium`은 네이버·인스타그램 자동 로그인에 쓸 브라우저를 내려받는 과정으로, 처음 한 번만 필요합니다.

### 2. 실행

```bash
npm start            # AutoM (블로그 전용)
npm run start:creator # AutoM Creator (블로그 + 인스타그램 + 유튜브)
```

### 3. 설정 화면에서 해야 할 일

1. **텍스트 AI**: Claude(Anthropic) · ChatGPT(OpenAI) · Gemini(Google) 중 하나를 고르고 API 키를 넣습니다.
2. **이미지 AI**: OpenAI 또는 Gemini 중 하나를 고르고 API 키를 넣습니다.
3. **연결 테스트**를 누릅니다. 성공하면 그 키와 모델이 **자동으로 저장**되고 사용할 AI로 지정됩니다.
4. **네이버**: 블로그 ID를 넣고 '네이버 로그인'을 눌러 열리는 창에서 로그인합니다.
   - 이때 **"로그인 상태 유지"를 반드시 켜 주세요.** 켜지 않으면 발행 단계에서 로그인이 풀립니다.
5. (Creator) **인스타그램**: 로그인 버튼을 눌러 열리는 창에서 로그인합니다.
6. **출력 폴더**: 결과물이 저장될 위치를 고릅니다.

> API 키는 Windows 자격 증명(Electron `safeStorage`)으로 **암호화되어 저장**되며, 화면에는 다시 표시되지 않습니다.
> 저장 여부와 마스킹된 일부만 보입니다.
> 연결 테스트와 콘텐츠 생성은 **실제 API 요청이므로 요금이 발생할 수 있습니다.**

## 코드 구조

프론트엔드와 백엔드가 **같은 3단 구조**를 사용합니다. 어느 쪽이든 "앱 껍데기 → 기능 → 공통 도구" 순서로 찾으면 됩니다.

```text
AutoM/
├─ frontend/                  # 사용자가 보는 화면
│  ├─ apps/blog|creator/      # 창의 HTML과 메뉴 전환만 담당
│  ├─ features/               # 화면 한 개 = 폴더 한 개
│  │  ├─ blog/ history/ settings/    # 두 앱이 공유 (base.js=기능, index.js=디자인)
│  │  └─ dashboard/ instagram/ youtube/   # Creator 전용
│  └─ shared/                 # 공통 디자인(styles), 로고(assets), 공통 도구(lib)
│
├─ backend/                   # 화면 뒤에서 실제 일을 하는 부분
│  ├─ apps/blog|creator/      # 창 생성, preload(창구), 앱 전용 IPC
│  ├─ core/                   # AI 공급자, 품질 검사, 예약 규칙 등 공통 핵심
│  ├─ features/blog|instagram|youtube/   # 플랫폼별 생성·로그인·발행
│  └─ shared/                 # 설정 저장, 발행 기록, 로그, 공통 IPC
│
├─ docs/                      # 사용자·개발 문서
├─ scripts/                   # 테스트, 구조 검사, QA, Chromium 준비
└─ package.json               # 실행·테스트·빌드 명령
```

화면은 파일이나 로그인 정보에 **직접 접근하지 못합니다.** preload가 공개한 `window.api`의 정해진 명령만 부를 수 있습니다.
(`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`)

자세한 내용은 [프로젝트 구조 문서](docs/architecture.md)를 참고하세요.

## 검사와 테스트

외부 서비스에 연결하지 않고, 실제 설정·API 키·발행 기록도 건드리지 않는 안전한 검사들입니다.

```bash
npm run check:architecture   # 필수 파일과 파일 간 연결이 끊기지 않았는지 확인
npm test                     # 품질 검사, 안전 기준, 예약 규칙 등 핵심 로직 (18개)
npm run test:creator         # 인스타그램·유튜브·설정 관련 로직 (27개)
npm run test:ui              # 두 앱을 실제로 띄워 모든 화면을 열어 보는 검사
npm run test:youtube-ui      # 유튜브 화면과 결과 화면 검사
```

`npm run test:ui`는 **화면이 영역을 넘어가는지**까지 자동으로 확인합니다.

- 창 크기 두 가지(1280×860, 1000×700)에서 모든 화면을 엽니다.
- 일부러 아주 긴 한글 제목·주소를 넣은 가짜 기록과 가짜 생성 결과를 그려 넣습니다.
- 가로 스크롤 발생, 잘린 버튼·입력칸, 카드 밖으로 삐져나온 글자, 중복 ID, 콘솔 오류, 외부 요청을 검사합니다.
- 화면 사진은 `output/ui-smoke/`에 저장됩니다.

### 디자인을 고칠 때

`frontend/shared/styles/app.css`는 규칙이 여러 겹으로 덮어쓰는 구조입니다. **순서를 바꾸면 겉모습이 달라집니다.**
순서에 영향을 주는 수정을 한다면 아래로 전후를 비교하세요. 34개 화면의 모든 요소를 비교해 한 곳이라도 달라지면 알려 줍니다.

```bash
node scripts/capture-style-snapshot.js before
# (수정)
node scripts/capture-style-snapshot.js after
node scripts/capture-style-snapshot.js compare
```

> 실제 AI 호출이 필요한 `npm run test:providers`는 **요금이 발생**하므로 환경변수로 키를 직접 넘길 때만 실행됩니다.

## 설치 파일 만들기

```bash
npm run build:win      # AutoM 설치 파일       -> dist/
npm run build:creator  # AutoM Creator 설치 파일 -> dist-creator/
```

빌드 전에 `npm run prepare:chromium`이 자동으로 실행되어 자동화용 Chromium과 영상 생성용 FFmpeg를 설치 파일에 포함시킵니다.

## 내 정보는 어디에 저장되나요

| 저장 내용 | 위치 |
|---|---|
| 설정과 API 키 (암호화) | Windows 사용자 데이터 폴더 |
| 네이버·인스타그램 로그인 세션 | 플랫폼별 Chromium 프로필 폴더 |
| 발행 기록 (`history.json`) | Windows 사용자 데이터 폴더 |
| 생성된 글·이미지·영상 | 설정에서 고른 출력 폴더 |

AutoM과 AutoM Creator는 서로 다른 폴더를 쓰므로 설정과 기록이 섞이지 않습니다.

## 자주 겪는 문제

**"네이버 로그인이 유지되지 않는 상태입니다"**
로그인할 때 **"로그인 상태 유지"** 체크를 켜지 않은 경우입니다. 설정에서 '세션 초기화' 후 다시 로그인하면서 체크를 켜 주세요.

**"자동·예약 발행에서는 이미 등록한 키워드를 다시 사용할 수 없습니다"**
같은 주제를 반복 발행하면 블로그 품질에 좋지 않아 막고 있습니다. 새로운 검색 의도의 키워드를 넣어 주세요.

**"앱이 생성한 PNG 이미지만 업로드할 수 있습니다"**
출력 폴더 밖의 파일은 안전을 위해 업로드하지 않습니다. 프로그램이 만든 결과 폴더의 파일을 사용하세요.

**연결 테스트가 실패해요**
API 키가 맞는지, 해당 계정에 결제 수단이나 잔액이 등록되어 있는지 확인하세요. 결제 상한 초과와 순간적인 요청 한도 초과는 서로 다른 안내 문구로 표시됩니다.
